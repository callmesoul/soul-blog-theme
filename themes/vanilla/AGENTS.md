# AGENTS.md

本文件供 AI 编码助手与本仓库协作时参考，说明项目的关键技术约定。

## UI 样式实现约定

- 本项目 UI 样式**统一使用 Tailwind CSS（v4）实现**。不要引入其他 CSS 框架，也不要把"再写一套自定义 CSS"作为新增样式的默认路径。

- 接入方式：

  - Vite 插件：`@tailwindcss/vite`，已在 `vite.config.js` 注册。

  - 样式入口：`src/css/style.css` 顶部通过 `@import "tailwindcss";` 加载 Tailwind。

- 布局、间距、字号、颜色、圆角、hover 等一律优先使用 Tailwind 工具类书写（含 JS 模板字符串中动态生成的 DOM）。

- Tailwind v4 通过扫描源码自动生成样式，因此：

  - 类名必须以**完整字面量**出现在源文件中；

  - 禁止用字符串拼接动态拼出类名（如 `` `bg-${color}-500` ``），否则对应样式不会被生成，需改用完整类名映射或内联 CSS 变量。

- 如需少量工具类难以表达的自定义视觉（如品牌渐变、主题字号微调、复杂组件状态），集中追加在 `src/css/style.css` 末尾的普通 CSS 规则中（其中 `:root` 已定义品牌色板，如 `--brand-primary: #EB4F38`），不要新建独立 CSS 文件，也不要为 UI 单独引入全局样式表。

- 修改既有组件结构时，保持与 `style.css` 既有自定义组件样式的兼容。

## 页面组件化约定

- 新增或修改页面时，**默认采用组件组合的方式实现**，并在合理范围内尽量组件化；页面入口只保留页面级布局、语义结构和组件挂载，不直接堆放大段可独立维护的 DOM。

- 公共区域（如背景、侧栏、播放器）、跨页面复用区块，以及拥有独立结构或交互职责的复杂区块，应拆到 `src/js/components/` 下的独立组件中；优先复用或扩展已有组件，禁止在多个页面复制同一份结构。

- 组件应保持单一职责，通过属性、参数或明确的数据接口接收差异内容，避免读取不必要的页面全局状态；组件内部结构、组件交互逻辑与页面初始化逻辑应有清晰边界。

- 页面入口、组件入口、公共模板函数和复杂交互必须添加简洁中文注释，说明组件职责、关键属性或数据流；注释应解释“为什么”和边界条件，避免逐行复述代码或堆积无信息量注释。

- 组件化以可维护性为准：无需把单个标签、一次性短文案或没有独立职责的微小片段机械拆成组件，但文章列表、表单、阅读器等完整功能区不应继续写成页面内的大段静态标记。

- 当前项目使用原生 JavaScript Web Components 实现轻量组件，不为组件化额外引入前端框架。组件模板中的 Tailwind 类同样必须使用完整字面量，确保 Tailwind v4 能正确扫描。

## 工程命令

- `npm run dev` — 本地开发预览

- `npm run build` — 构建产物（输出到 `dist/`）

- 提交前如改动涉及 UI，先执行 `npm run build` 确认 Tailwind 扫描与构建通过。

## 提交约定

- 每次提交前必须同步更新并完善 `README.md` 与 `CHANGELOG.md`：

  - 新增或调整功能、脚本、目录结构、配置项或使用方式时，在 `README.md` 中补齐对应说明；

  - 在 `CHANGELOG.md` 的 `[Unreleased]` 段按「Added / Changed / Fixed / Removed」分类记录本次变更。
