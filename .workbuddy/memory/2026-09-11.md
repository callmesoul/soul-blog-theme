## 把各主题 dev server 跑起来（WSL 环境坑）

- 运行环境：Bash 工具实际是 Windows Git Bash，cwd 是坏的；WSL 路径要用 `wsl.exe --cd /home/callmesoul/code/soul-blog-theme -- bash -c '...'` 进 WSL 内执行。
- **pnpm 在 WSL 内被 Windows PATH 污染**：解析到 `\wsl.localhost\...\nvm4w\...` 的坏路径跑不起来。改用各目录里的 `node_modules/.bin/vite` / 测试站点的 `node_modules/.bin/hexo` 直接调用（需先 `export PATH=/home/callmesoul/.nvm/versions/node/v24.21.0/bin:...` 让 node 可达）。
- 端口现状（截至本日）：vanilla=5173、vue=5175（5174 被另一个项目 dropspot-workplace/electron-vite 占着，所以 vue 自动落到 5175）、react=5176、hexo=4000。
- hexo 主题不是独立 dev server：需 `themes/hexo` 先 `vite build`（输出到 themes/hexo/source/）→ 整目录 cp 到 `/tmp/hexo-test/themes/hexo` → `hexo clean && hexo generate` → `hexo server -p 4000`。第一次 build 偶发报错，重跑一次就过。
- **关键坑：在 `wsl.exe -- bash -c` 里用 `nohup ... &` 起的后台进程会在该次命令结束后被回收**，导致 hexo 起完又挂。正确做法是用 Bash 工具的 `run_in_background: true`（foreground 跑 `hexo server`，用 `exec` 替换 shell），由任务管理器常驻。
- 已存在服务（vanilla/vue/react）是用户在自己的 WSL shell 里起的，能跨命令存活，无需我重启。

## 访问统计最终改用 Vercount

- 不蒜子方案无法为首页文章列表提供只读批量查询，最终改用 Vercount 公开 API。
- 列表对当前渲染卡片发起只读 GET，打开文章时以 `/articles/{id}` 稳定路径 POST 记录 PV；四套主题共用 `packages/core/src/helpers/vercount.ts`。
- 站点 PV / UV、首页卡片和阅读器计数都有请求加载动效、`aria-busy` 与失败回退；快速切文时使用请求序号防止旧响应覆盖新计数。
- Hexo 测试站需同步主题到 `/tmp/hexo-test/themes/hexo`、重新 generate 并重启 4000 端口；本次已完成并用页面产物确认 Vercount 代码生效。
